# Telegram Catalog

Каталог товаров с управлением через Telegram-бота. Администратор отправляет фото
и название товара одним сообщением; товар становится доступен в веб-каталоге
и Telegram Mini App.

## Возможности

- Добавление товаров администраторами из списка `ADMIN_IDS`.
- Хранение названий и метаданных в PostgreSQL, изображений — в приватном bucket MinIO.
- Каталог с поиском по названию и курсорной пагинацией.
- Один интерфейс для обычного браузера и Telegram Mini App.
- Защита от повторного создания товара при повторной обработке одного сообщения.
- Несколько stateless-экземпляров API, бота и frontend.
- Миграции базы данных, health checks и автоматические тесты.

## Стек и архитектура

| Компонент | Технология | Назначение |
|---|---|---|
| Веб-интерфейс | Next.js App Router, React, TypeScript | SSR каталога и Mini App |
| API | FastAPI, SQLAlchemy, Alembic | Валидация, запись и чтение товаров |
| Telegram-бот | aiogram 3, FastAPI webhook | Команды и обработка фотографий |
| База данных | PostgreSQL | Товары и очередь Telegram-обновлений |
| Файловое хранилище | MinIO, S3 API | Изображения товаров |
| Входной прокси | Nginx | Маршрутизация и распределение запросов |
| Запуск | Docker Compose | Сборка и запуск окружения |

Webhook сохраняет обновление в PostgreSQL до подтверждения получения.
Обработчики забирают задания через `FOR UPDATE SKIP LOCKED`; аренда задания
позволяет повторить обработку после сбоя. Уникальный ключ исходного сообщения
и транзакционная блокировка защищают создание товара от дубликатов.

Реплики приложения не хранят пользовательские файлы и состояние диалога локально.
Frontend запрашивает актуальные данные без кеширования; изображения выдаёт API.
Подробности и границы гарантий описаны в [ARCHITECTURE.md](docs/ARCHITECTURE.md).

## Локальный запуск

Требуются Docker с Compose, Python 3 для генерации конфигурации и доступ к интернету
для первой сборки. На Windows используется Docker Desktop с Linux containers.

В корневой папке проекта:

```powershell
python scripts/setup_env.py
docker compose up -d --build
```

Скрипт создаёт `.env` со случайными секретами и не перезаписывает существующий файл.
Сервис `init` выполняет миграции и создаёт bucket, затем завершается.
MinIO собирается из фиксированного исходного release, поэтому первая сборка
может занять дополнительное время.

Каталог: [http://localhost:8080](http://localhost:8080).

Для демонстрации без подключения Telegram можно добавить четыре тестовых товара:

```powershell
docker compose exec bot python -m app.manage seed
```

Повторный запуск этой команды не создаёт дубликатов.

## Конфигурация

Параметры задаются в `.env`; шаблон доступен в [.env.example](.env.example).

| Переменная | Назначение |
|---|---|
| `BOT_TOKEN` | Токен Telegram-бота |
| `ADMIN_IDS` | Числовые Telegram ID администраторов через запятую |
| `PUBLIC_BASE_URL` | Публичный HTTPS-адрес без завершающего слеша |
| `PORT` | Локальный порт входного прокси; по умолчанию 8080 |
| `POSTGRES_PASSWORD` | Пароль PostgreSQL |
| `S3_ACCESS_KEY`, `S3_SECRET_KEY` | Доступ к MinIO |
| `INTERNAL_API_TOKEN` | Авторизация внутренних запросов бота к API |
| `WEBHOOK_SECRET` | Проверка источника webhook-запросов |

`.env` исключён из Git. Для отдельного окружения используются собственные секреты
и токен бота. Одна база данных обслуживает одного Telegram-бота.

## Подключение Telegram

1. Создать бота через [@BotFather](https://t.me/BotFather) и задать `BOT_TOKEN`.
2. Настроить публичный HTTPS-адрес, ведущий на порт 8080, и указать его
   в `PUBLIC_BASE_URL`. Этот адрес обслуживает и каталог, и `/telegram/webhook`.
3. Применить настройки и зарегистрировать webhook:

```powershell
docker compose up -d api bot
docker compose exec bot python -m app.manage set-webhook
docker compose exec bot python -m app.manage webhook-info
```

4. Отправить боту `/id`, добавить полученный ID в `ADMIN_IDS` и применить настройку:

```powershell
docker compose up -d bot
```

Для локальной демонстрации с установленным cloudflared:

```powershell
cloudflared tunnel --url http://localhost:8080
```

Туннель должен оставаться запущенным. При изменении его адреса необходимо обновить
`PUBLIC_BASE_URL`, применить настройки и повторно зарегистрировать webhook.
Временный туннель не является постоянным размещением приложения.

## Команды бота

| Команда | Действие |
|---|---|
| `/start` | Сообщение «У меня есть товары» и кнопка каталога |
| `/id` | Telegram ID пользователя |
| `/create` или «Создать товар» | Инструкция добавления для администратора |

После `/create` администратор отправляет одно фото с названием в подписи.
Название — до 200 символов, изображение — до 5 МБ. Альбомы не поддерживаются.
Административные команды доступны только в личном чате. После добавления бот
подтверждает создание товара и предлагает открыть каталог.

## Масштабирование

```powershell
docker compose up -d --scale api=2 --scale bot=2 --scale web=2
docker compose ps
```

Nginx распределяет запросы между репликами. Все экземпляры используют общие
PostgreSQL и MinIO; регистрация webhook выполняется отдельно от запуска реплик.

Для проверки перезапуска сервисов приложения:

```powershell
docker compose restart api bot web
```

После запуска следует обновить каталог и проверить доступность ранее добавленных товаров.

## Тестирование

Тесты используют отдельную PostgreSQL БД `catalog_test` и временные buckets MinIO:

```powershell
docker compose --profile test build tests
docker compose --profile test run --rm tests
```

Последний подтверждённый запуск на Windows с Docker Desktop, 26 октября 2026 года:
**34 passed**, без пропусков.

Проверяются права администратора, webhook secret, валидация изображений,
поиск и пагинация, идемпотентность, конкурентное создание товаров,
распределение заданий и восстановление после истечения аренды.

В GitHub Actions настроены backend-тесты и production-сборка frontend со smoke-проверкой.
Результаты ручных проверок и оставшиеся проверки: [VERIFICATION.md](docs/VERIFICATION.md).

## Диагностика и остановка

```powershell
docker compose logs --tail=100 api bot
docker compose exec bot python -m app.manage queue-status
docker compose exec bot python -m app.manage webhook-info
```

После устранения причины ошибки задания можно вернуть в очередь:

```powershell
docker compose exec bot python -m app.manage retry-failed
```

Остановка с сохранением данных в именованных volumes:

```powershell
docker compose down
```

Параметр `-v` удаляет volumes с данными.

## Ограничения

- Объём реализации — добавление и просмотр товаров; корзина, заказы и оплата не реализованы.
- PostgreSQL, MinIO и Nginx представлены по одному экземпляру. Compose демонстрирует
  масштабирование приложения, а не полную отказоустойчивость инфраструктуры.
- Повторная обработка не дублирует товар, но после сбоя возможен повторный ответ бота.
- Запись в PostgreSQL и MinIO не является общей транзакцией; после сбоя возможен
  объект без записи товара. Автоматическая очистка таких объектов не реализована.
