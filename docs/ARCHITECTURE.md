# Устройство проекта

## Компоненты

| Компонент | Обязанность | Постоянные данные |
|---|---|---|
| Next.js | SSR каталога, поиск, Mini App SDK | нет |
| FastAPI API | валидация и запись товара, выдача списка и фото | PostgreSQL + MinIO |
| aiogram / webhook | приём Telegram update, команды, отправка товара в API | PostgreSQL inbox |
| PostgreSQL | товары, уникальные ключи, очередь, lease | volume |
| MinIO | приватные изображения | volume |
| Nginx | один внешний адрес, распределение по репликам | конфигурация |

## Один товар от сообщения до страницы

1. Telegram отправляет JSON на `/telegram/webhook`.
2. Webhook проверяет секретный заголовок, валидирует размер и формат JSON.
3. `INSERT ... ON CONFLICT DO NOTHING` сохраняет update. HTTP 200 возвращается после commit.
4. Один worker забирает update через `FOR UPDATE SKIP LOCKED` и получает lease на 120 секунд.
5. aiogram проверяет private chat и Telegram user ID по allowlist.
6. Фото скачивается в ограниченный BytesIO; локальный файл не создаётся.
7. Worker отправляет название, base64 фото и стабильный ключ исходного сообщения в API.
8. API проверяет внутренний bearer token, изображение и размер. Берёт транзакционный
   advisory lock для source key. Проверяет повтор и несовпадающий payload.
9. Байты записываются в MinIO под SHA-256 ключом, затем в транзакции фиксируется товар.
10. Бот отвечает пользователю; worker помечает update выполненным и очищает JSON payload.
11. Next.js получает свежий список из API, браузер запрашивает фото через `/api/products/{id}/image`.

Изображение отдаётся API, а не ссылкой на внутренний hostname MinIO. Поэтому одинаково
работают localhost, HTTPS-туннель и Telegram Mini App; bucket не нужно делать публичным.

## Что значит stateless

Реплики не содержат бизнес-данных, которые потеряются при перезапуске. DB pool, HTTP client,
конфигурация и выполняющаяся coroutine живут в памяти — это нормально. Источником истины
для товаров и незавершённых обновлений остаются внешние хранилища.

FSM выключена: фото и подпись приходят в одном сообщении, поэтому состояние «ожидаем фото»
не требуется. Frontend динамический, без ISR/Data Cache и файлового image optimizer.
`api`, `bot`, `web` запускаются с `read_only: true`; сборочные файлы Next.js только читаются.

## Повторы, сбои и гарантии

- Повтор одного webhook не создаёт второе задание: первичный ключ `update_id`.
- Параллельная доставка одного товара двум API сериализуется транзакционным advisory lock.
  UNIQUE(source_key) дополнительно защищает базу. Повтор с другими данными получает HTTP 409.
- При падении worker lease истекает, задание снова доступно. Старый worker не может
  подтвердить уже перевыданный job: обновление требует совпадения UUID lease_token.
- Таймаут обработки 60 секунд меньше lease 120 секунд. После ошибок есть backoff и
  ограничение 8 попыток; исчерпанные jobs доступны через `queue-status` / `retry-failed`.
- Успех добавления товара не означает exactly-once отправку ответа в Telegram:
  сбой после `sendMessage`, но до отметки processed, может привести к повторному ответу.
  Сам товар при этом не дублируется.
- Между PostgreSQL и S3 нет распределённой транзакции. Сбой после записи S3 и до commit
  может оставить объект без товара. Повтор использует тот же hash key. Очистка orphan
  объектов не реализована; не удаляйте их автоматически без учёта выполняющихся записей.
- До commit inbox HTTP-ошибка позволяет Telegram повторить доставку. После commit за
  повторную обработку отвечает наша DB queue.
- Маркеры завершённых update_id сохраняются для дедупликации. Политика их долговременной
  очистки не реализована; payload успешных задач уже очищен.

## Границы отказоустойчивости

Compose демонстрирует отказоустойчивость и масштабирование приложения. Это не production
HA всей системы: PostgreSQL, MinIO и Nginx представлены одним экземпляром. Для реального
HA нужны управляемая/реплицируемая БД, distributed MinIO и резервируемый балансировщик,
резервные копии, мониторинг и проверка восстановления. Само наличие двух stateless
реплик не делает одиночное хранилище отказоустойчивым.

Секреты общие для реплик и передаются через окружение. Развёртывание использует одну
версию образа Next.js для всех реплик. Sticky sessions не нужны.

## Упрощения учебного проекта

- S3 credentials в Compose относятся к локальному MinIO root account. Для постоянного
  публичного окружения создайте отдельный bucket-scoped service account.
- Base64 в JSON добавляет около 33% к размеру запроса, но упрощает ограничение размера
  и полностью исключает multipart-файлы на локальном диске. Лимит изображения 5 МБ.
- API загружает фото целиком, но размер ограничен. Для больших файлов понадобится streaming.
- У публичного каталога нет личных данных. Админские действия выполняются только через
  серверную проверку Telegram user ID, а не через данные из браузера.
- Лимиты запросов и общий антиспам для публичного webhook/каталога следует добавить
  при реальной публичной эксплуатации. Секретный webhook защищает источник запросов,
  но не запрещает обычным пользователям писать боту.
