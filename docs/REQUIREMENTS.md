# Область реализации

Проект реализует размещение товаров через Telegram-бота и просмотр каталога
в браузере и Telegram Mini App согласно подробному техническому заданию.

| Требование | Реализация |
|---|---|
| Команда создания товара для администратора | `/create` и текст «Создать товар» |
| Название + фото в одном сообщении | `message.photo` + `message.caption` |
| Файл в MinIO, запись в PostgreSQL | приватный bucket + таблица products |
| Каталог на Next.js App Router | `frontend/app/page.tsx` |
| Браузер и Telegram Mini App | один URL, Telegram WebApp-кнопка и SDK |
| FastAPI + aiogram 3.x | отдельные API и webhook/worker сервисы |
| Сообщение «У меня есть товары» | `/start` и обычные обращения |
| Несколько stateless экземпляров | DB inbox, leases, idempotency, без локальных файлов |
| Ссылка GitHub/GitLab | [Kirill-dev01/telegram-catalog](https://github.com/Kirill-dev01/telegram-catalog) |
| Демо «если развёрнуто» | локальный Docker Compose; доступ через временный HTTPS-туннель проверен, постоянный хостинг не настроен |
| Выполнить без AI | не соблюдено: при разработке использовались AI-инструменты |

## Решения там, где ТЗ не уточняет детали

- Администраторы задаются числовыми Telegram ID в переменной окружения.
- Каталог публичный, поэтому авторизация покупателя и проверка `initData` не нужны для чтения.
  Если появятся персональные данные или покупки, на backend потребуется проверять Telegram initData.
- Веб-админки нет: добавление происходит через бота.
- Товар содержит название и одно фото, без цены, остатка или категории.
- Страница SSR использует `no-store`; нет Server Actions, ISR и оптимизации изображений на диске.
- Бот использует webhook, не long polling. Одна БД обслуживает один Telegram bot token.
- Дополнения для удобства: поиск, пагинация, `/id`, demo seed, диагностика очереди.

## Границы функциональности

Реализованы добавление товара и просмотр каталога. Корзина, оформление заказа,
оплата и отдельная страница товара не входят в реализованный объём.

## Границы развёртывания

Несколько экземпляров поддерживают сервисы приложения `api`, `bot` и `web`.
PostgreSQL, MinIO и Nginx в текущем Compose работают в одном экземпляре.
Это ограничение инфраструктуры описано в [ARCHITECTURE.md](ARCHITECTURE.md).
Временный HTTPS-туннель доступен только при работающих компьютере, Docker и процессе туннеля.
